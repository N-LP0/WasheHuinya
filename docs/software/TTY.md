# TTY-доступ

## Общая схема

Устройство имеет два разных интерфейса:

- HID: компьютер видит ESP32-S3 как USB-клавиатуру/мышь или как выбранное BLE HID-устройство.
- Wi-Fi TTY API: команды отправляются на устройство по HTTP, а TTY-лог передается через WebSocket.

В текущей прошивке `TTY` означает командный интерфейс по Wi-Fi. Это не управление через Linux-устройство `/dev/tty*`. В рабочем режиме USB используется как HID-интерфейс, а не как serial monitor.

HID-события отправляются через транспорт, выбранный на вкладке `HID / BLE`. В USB-режиме получателем является USB-хост. В BLE-режиме получателем является сопряженный Bluetooth-компьютер.

## Подключение по Wi-Fi

Если устройство работает в режиме точки доступа, подключи компьютер к Wi-Fi сети устройства и открой:

```text
http://192.168.4.1
```

Если устройство подключилось к твоей Wi-Fi сети, открой:

```text
http://hidpad-s3.local
```

Также можно использовать IP-адрес устройства из роутера или DHCP-сервера.

## Разрешение имени `hidpad-s3.local`

Чтобы на Debian/Ubuntu работало имя `hidpad-s3.local`, установи Avahi:

```bash
sudo apt install avahi-daemon libnss-mdns
sudo systemctl enable --now avahi-daemon
```

Проверка:

```bash
ping hidpad-s3.local
```

Если `.local` не работает, используй IP-адрес устройства напрямую.

## Firewall

Linux должен разрешать исходящие подключения к устройству:

- TCP `80` - web UI и HTTP API;
- TCP `81` - WebSocket для TTY-лога.

На большинстве desktop-дистрибутивов исходящие подключения разрешены по умолчанию.

## USB HID

Для работы USB-клавиатуры и мыши обычно не нужны специальные права. Linux должен увидеть устройство как обычное USB HID устройство.

В USB-режиме прошивка одновременно предоставляет клавиатуру и мышь. В BLE-режиме активна только выбранная роль, а USB-кабель можно оставить для питания.

Полезные команды для проверки:

```bash
lsusb
dmesg -w
```

Если HID-события приходят не туда, проверь выбранный транспорт. Для USB проверь кабель и USB-хост, для BLE - текущее Bluetooth-сопряжение.

## BLE HID

BLE включается на вкладке `HID / BLE` и работает в одной роли за загрузку:

- `HIDPad S3 keyboard` - команды `TEXT`, `TYPE`, `KEY`, `HOTKEY` и клавиатурная часть `RELEASEALL`;
- `HIDPad S3 mouse` - команды `MOUSE ...` и мышиная часть `RELEASEALL`.

Смена транспорта или BLE-роли сохраняет конфигурацию и перезагружает устройство, потому что HID report map создаётся при запуске BLE-сервиса. Pairing использует bonding без PIN-кода. Wi-Fi и BLE работают одновременно через встроенный ESP32-S3 coexistence-механизм.

На вкладке `HID / BLE` отображаются сохраненные bonds. Можно удалить одно сопряжение по Bluetooth-адресу или очистить весь список. Операция удаляет ключи на ESP32-S3; после этого удали устройство и на стороне компьютера или телефона, затем выполни pairing заново. Управление bonds доступно только в режиме `Bluetooth LE`.

Во время pairing RGB-светодиод быстро мигает голубым. После подключения BLE HID он постоянно горит голубым, если в этот момент не выполняется макрос.

Windows может кэшировать имя, PnP ID и HID descriptor. После смены роли или обновления BLE-идентификаторов удали старое устройство из Bluetooth-настроек и Device Manager, затем выполни pairing заново.

## USB CDC и режим прошивки

В рабочем HID-режиме прошивка не включает USB CDC на старте, поэтому обычный COM-порт для serial monitor подниматься не должен.

В ROM download mode или во время прошивки ESP32-S3 может появляться отдельный UART/USB CDC порт, например `COM14` на Windows или `/dev/ttyACM0` на Linux. Этот порт создаётся загрузочным режимом чипа и нужен инструментам прошивки. Рабочая прошивка не использует его как TTY-интерфейс.

Если на Linux нужно прошивать устройство через этот порт, пользователь должен иметь доступ к serial-устройствам.

Debian/Ubuntu:

```bash
sudo usermod -aG dialout "$USER"
```

Arch Linux:

```bash
sudo usermod -aG uucp "$USER"
```

После изменения группы нужно выйти из сессии и войти снова.

На некоторых системах `ModemManager` может мешать прошивке через serial-порт:

```bash
sudo systemctl disable --now ModemManager
```

Отключай `ModemManager` только если он не нужен для мобильных модемов.

## TTY-аутентификация

TTY-аутентификация опциональна.

- Если `TTY password` пустой, TTY-доступ открыт.
- Если `TTY password` задан, HTTP TTY-команды и WebSocket TTY-лога требуют токен.
- `Disable TTY auth` отключает проверку TTY-токена.
- `Access token` в TTY-панели web UI хранится в `localStorage` браузера.

Ошибка неверного токена:

```json
{"error":{"code":"tty_unauthorized","message":"TTY token is invalid"}}
```

## HTTP TTY-команды

Выполнить TTY-команду:

```bash
curl -X POST \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data-urlencode "cmd=HELP" \
  --data-urlencode "token=your-token" \
  http://hidpad-s3.local/api/tty/exec
```

Если TTY-аутентификация отключена, поле `token` можно не передавать.

Успешный ответ:

```json
{"ok":true,"data":{"output":"HELP | PING | RUN <profile> | STOP | LINE <macro_line>"}}
```

Получить текущий TTY-лог через совместимый HTTP endpoint:

```bash
curl "http://hidpad-s3.local/api/tty/log?token=your-token"
```

Успешный ответ:

```json
{"ok":true,"data":{"log":"TTY ready\n"}}
```

## WebSocket TTY-лога

Web UI подключается к TTY-логу через WebSocket:

```text
ws://hidpad-s3.local:81/?token=your-token
```

При подключении WebSocket отправляет текущий TTY-лог. После этого новые сообщения приходят при изменении лога.

Если устройство работает в AP-режиме, можно использовать:

```text
ws://192.168.4.1:81/?token=your-token
```

## Поддерживаемые TTY-команды

```text
HELP
PING
RUN <profile>
STOP
LINE <macro_line>
```

`RUN` запускает профиль. Повторы задаются внутри текста макроса командами `REPEAT`, `LOOP` и `END`.

Примеры:

```text
RUN hello
RUN mouse_test
STOP
LINE KEY CTRL ALT T
LINE TEXT git status
LINE KEY ENTER
```

Команда `LINE` выполняет одну строку макроса без сохранения профиля. Для отладки многострочного макроса удобнее использовать кнопку `Test` в web UI, потому что она запускает весь текст из редактора без сохранения.

## Диагностика

### Web UI открывается, но TTY-команды не выполняются

Проверь поле `Access token` в TTY-панели. Если TTY-аутентификация включена и токен неправильный, API вернет:

```json
{"error":{"code":"tty_unauthorized","message":"TTY token is invalid"}}
```

### TTY-лог не обновляется

Проверь, что TCP порт `81` доступен и не заблокирован firewall.

Если WebSocket недоступен, можно использовать совместимый HTTP endpoint:

```text
GET /api/tty/log
```

### `hidpad-s3.local` не открывается

Установи и запусти Avahi или используй IP-адрес устройства напрямую.

### HID-события приходят не туда

Проверь выбранный транспорт на вкладке `HID / BLE`. Для USB проверь подключенный хост, для BLE - сопряжение и статус `connected`.

### BLE-устройство отображается под старым именем

Удаление только из списка Bluetooth иногда не очищает кэш Windows. Удали соответствующее устройство также в Device Manager, перезагрузи Bluetooth-адаптер или Windows и выполни сопряжение заново.
